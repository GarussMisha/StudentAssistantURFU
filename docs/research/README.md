# Исследования требований — план

## Методология

1. Один документ — одна область. Документ самодостаточен.
2. Цикл: факты из кода → вопросы фронтира → решения → контракты → edge cases → критерии приёмки.
3. Решения нумеруются (`UI-01`, `RAG-03`) и не удаляются: отмена оформляется новым решением.
4. Документ готов, когда не осталось открытых вопросов, влияющих на реализацию.
5. Исследования живут в `docs/research/`, вне `openspec/`; SDD строится ПО НИМ.

## Порядок

01 (готово) → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10.
Один документ = 1–2 раунда интервью (30–60 минут).

## Шаблон документа

- Контекст и цель
- Факты из кодовой базы
- Пользователи и сценарии
- Требования (FR)
- Контракты и точки интеграции
- Граничные случаи
- НФТ
- Критерии приёмки
- Журнал решений
- Открытые вопросы / бэклог
