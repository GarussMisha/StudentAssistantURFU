## 1. Контекст и цель

История и оценки — то, что отличает ассистента от одноразового чата: студент
возвращается к своим вопросам, а автор продукта получает обратную связь.
Документ фиксирует поведение чатов, сообщений и оценок: заголовки, группировку,
ленту, удаление, повтор, семантику лайков.

Технические формы (таблицы, эндпоинты, SSE) уже определены в 03; здесь —
**поведение** и правила, которые 03 не покрывает.

## 2. Факты из кодовой базы

- Кода нет: `app/services/`, `app/db/` пусты; таблицы `chats`, `messages`,
  `message_ratings` описаны только в 03 §5.1.
- 03 §FR-6/FR-7: список чатов с keyset-курсором, ленивая история, `PUT /rating`
  как upsert, `POST /api/profile/history/delete`.
- 01 §5: заголовок 60 символов, группировка «Сегодня / Вчера / На этой
  неделе / В этом месяце / Ранее», активный чат подсвечен.
- 02 FR-6: оценка сохраняется сразу, восстанавливается после перезагрузки, может
  быть изменена; удаление отдельного чата — бэклог.
- 02 PR-06: история хранится бессрочно, пользователь может удалить всю.
- 05 RAG-19: `meta` сообщения содержит служебные данные (`attempts`, `top_score`
  и т.п.), наружу не отдаётся.
- Заголовок — 60 символов в 01/03; алгоритм обрезки фиксирует CONV-01.

## 4. Функциональные требования

### FR-1. Жизненный цикл чата

- Чат создаётся **первым непустым вопросом** (03 CC-27); «Новый чат» — локальный
  пустой экран без записи в БД.
- Заголовок (CONV-01): первый вопрос → снять Markdown-разметку, схлопнуть
  пробелы → обрезать до **60 символов** по границе слова (если остаток после
  обрезки ≥ 10 символов, иначе ровно 60) + `…` при обрезке.
- Если после очистки меньше 3 символов (эмодзи, знаки) → «Новый чат».
- Заголовок фиксируется навсегда: не перегенерируется, не редактируется
  (переименование — бэклог).
- `created_at` — момент создания, `updated_at` — момент последнего **сообщения**
  (не оценки, не открытия).

### FR-2. Список чатов и группировка

- `GET /api/chats?limit=15&cursor=…` — только чаты с сообщениями, сортировка
  `updated_at DESC, id DESC`.
- Правила группировки задаёт сервер (`APP_TIMEZONE=Asia/Yekaterinburg`,
  CONV-02); в JSON группировка не передаётся — UI группирует по `updated_at`
  тем же правилам:
  - «Сегодня» — с 00:00 текущих локальных суток;
  - «Вчера» — предыдущие локальные сутки;
  - «На этой неделе» — с понедельника текущей недели;
  - «В этом месяце» — текущий календарный месяц;
  - «Ранее» — всё остальное.
- В БД время UTC; в JSON — ISO-8601 с `Z`; сервер отдаёт только `updated_at`
  и встраивает `APP_TIMEZONE` в HTML, чтобы UI не дублировал конфиг. Часовой
  пояс фиксирован на сервере.
- Список не переупорядочивается при оценке (CONV-05).
- Пустой список → `items: []`, UI показывает «Пока нет чатов. Начните новый».

### FR-3. Лента сообщений

- `GET /api/chats/{id}/messages?limit=2` — первая загрузка (03 CC-24).
- Прокрутка вверх → `before_seq` + `limit=20`; `has_more` управляет кнопкой
  «Загрузить ещё».
- Сообщения `no_reply` отображаются как «Ответ не получен» с кнопкой
  «Повторить»; `stopped` — «Ответ остановлен» с сохранённым текстом.
- Источники рендерятся из снимка `sources`; после переиндексации корпуса
  история не меняется (03 CC-05).
- Пустой чат невозможен по конструкции; `deleted` сообщений нет.

### FR-4. Оценки

- Одна оценка на сообщение, `UNIQUE(message_id)`, только assistant-сообщения
  своих чатов (03 CC-13).
- Назначение — **сбор обратной связи** для улучшения продукта и eval
  (CONV-05): оценка **не** влияет на генерацию, не попадает в контекст, не
  меняет порядок чатов, не меняет статус сообщения.
- `PUT /api/messages/{id}/rating {value, comment?}` — идемпотентный upsert;
  `value: null` удаляет оценку и комментарий.
- Оценка ставится на сообщения с любым статусом (`grounded`, `ungrounded`,
  `no_answer`, `stopped`), кроме `no_reply` — у него нет содержания, UI кнопок
  не показывает. Сервер в этом случае отвечает `404 not_found`.
- Повторное нажатие того же значения не снимает оценку (нужно `value: null`,
  UI такого не делает — оценка «залипает» до смены).
- Оценка восстанавливается при загрузке ленты (поле `rating` в `Message`).

### FR-5. Комментарий

- Комментарий существует только вместе с оценкой (03 CC-13).
- Нажатие лайка/дизлайка отправляет `{value}` и открывает поле «Дайте
  комментарий».
- Ввод комментария — повторный `PUT` с `{value, comment}`; пустая строка
  очищает комментарий, оценка остаётся.
- Лимит 1000 символов; ошибка — под полем, оценка при этом уже сохранена.
- Отдельного эндпоинта «только комментарий» нет.

### FR-6. Удаление истории

- `POST /api/profile/history/delete {confirm: true}` → 200
  `{deleted_chats: N}`.
- Удаление **жёсткое**, одной транзакцией: `DELETE FROM chats WHERE user_id=?`,
  каскад на `messages` и `message_ratings` (CONV-03).
- Активный SSE-стрим в удаляемом чате отменяется кооперативно; частичный ответ
  не сохраняется (чат всё равно удалён).
- UI после успеха: очищает меню, редиректит на `/`, toast «История удалена».
- `deleted_chats = 0` — не ошибка (200).
- Восстановление невозможно; в модалке обязателен чекбокс (01 UI-12).

### FR-7. Повтор после `no_reply`

- Отдельного эндпоинта нет (CONV-04): кнопка «Повторить» подставляет текст
  вопроса в поле ввода.
- Отправка создаёт **новое** сообщение; лимит 40 учитывает обе попытки.
- Старое `no_reply` остаётся в истории без изменений.
- Редактирование и удаление отдельных сообщений — вне скоупа.

### FR-8. Потолок чата

- 40 сообщений (20 пар user + assistant), `CHAT_MAX_MESSAGES` (03 FR-8).
- При 40 сообщениях новая отправка (41-е) → `409 chat_limit_reached`, ввод
  блокируется, плашка «Создайте новый чат».
- Новый чат создаётся первым вопросом; старое остаётся доступным только для
  чтения.
- Лимит не влияет на удаление истории (удаляет все чаты целиком).

## 5. Контракты и точки интеграции

| Потребность | Контракт (03) |
|---|---|
| Создание чата | `POST /api/messages {chat_id: null, text}` |
| Список | `GET /api/chats` |
| Лента | `GET /api/chats/{id}/messages` |
| Оценка | `PUT /api/messages/{id}/rating` |
| Удаление истории | `POST /api/profile/history/delete` |
| Счётчики для профиля | `GET /profile` (HTML, счётчик чатов) |

Поля `Message` (`rating`, `sources`, `status`) — 03 §FR-6. Дополнительных полей
документ не вводит.

## 6. Граничные случаи

| Ситуация | Поведение |
|---|---|
| Вопрос из одних эмодзи | заголовок «Новый чат» |
| Вопрос длиннее 60 символов | обрезка по слову + `…` |
| Переход через полночь | «Сегодня» считается по локальным суткам сервера |
| Оценка старого чата | чат не поднимается в списке |
| Повторный PUT с тем же value | 200, `updated_at` оценки обновляется |
| Оценка `no_reply` | 404, кнопок в UI нет |
| Чужое сообщение | 404 |
| Удаление истории при активном стриме | стрим отменён, чат удалён, 200 |
| Удаление истории без чатов | 200, `deleted_chats: 0` |
| `confirm` отсутствует | 422 |
| Повтор после `no_reply` на 40-м сообщении | 409, сначала новый чат |
| Догрузка истории при `has_more=false` | UI не показывает кнопку |
| Оценка после удаления чата | 404 |
| Комментарий 1001 символ | 422, оценка сохранена |

## 7. НФТ

- **Скорость:** список (15 чатов) ≤ 200 мс, страница ленты (20 сообщений)
  ≤ 150 мс на локальной БД.
- **Консистентность:** удаление истории атомарно; частично удалённых чатов не
  бывает.
- **Приватность:** тексты чатов не логируются (03 CC-20); оценки и комментарии
  видны только владельцу.
- **Восстановление:** после перезагрузки страницы оценка, лента и группировка
  восстанавливаются без потерь.
- **Доступность:** `Asia/Yekaterinburg` без перехода на летнее время — границы
  суток стабильны круглый год.

## 8. Критерии приёмки

- [ ] Первый вопрос создаёт чат; заголовок ≤ 60 символов, не меняется.
- [ ] Список: 15 чатов, курсор, группировка по локальным датам.
- [ ] Лента: 2 сообщения при входе, догрузка по 20, `has_more` корректен.
- [ ] Оценка сохраняется сразу, восстанавливается после перезагрузки,
      изменяется и удаляется (`value:null`).
- [ ] Оценка не влияет на порядок чатов и на контекст следующих ответов.
- [ ] Комментарий без оценки невозможен; пустая строка очищает комментарий.
- [ ] Удаление истории: каскад, `deleted_chats`, редирект, пустое меню.
- [ ] «Повторить» создаёт новое сообщение, старое `no_reply` остаётся.
- [ ] При 40 сообщениях новая отправка → 409 и плашка; новый чат создаётся.
- [ ] Все чужие объекты → 404, не 403.
