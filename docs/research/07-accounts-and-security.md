## 1. Контекст и цель

Аккаунт — единственный вход в продукт: без сессии недоступны ни чат, ни история.
Документ фиксирует регистрацию, вход/выход, смену и **ручной** сброс пароля,
жизненный цикл сессий, защиту от перебора, хранение паролей и минимизацию ПДн.

Отдельно фиксируется важное организационное решение: **в приложении нет роли
«администратор»**. Администратор — это человек с доступом к серверу и CLI;
веб-интерфейс одинаков для всех.

## 2. Факты из кодовой базы

- `app/core/config.py`: `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SESSION_TTL_DAYS=7`;
  зависимости `argon2-cffi`, `python-multipart` уже стоят.
- Кода аутентификации нет: `app/api/`, `app/services/` пусты; таблицы

- 01 §4: вкладки входа/регистрации, обязательный чекбокс согласия, модалка

- `AGENTS.md` и `README.md` синхронизированы с 04 (`data/kb/md/`); F-07 закрыт.
- Домашний сервер: 12 ядер, 16 ГБ RAM, без GPU — Argon2 можно не экономить.

## 4. Функциональные требования

### FR-1. Регистрация

- Поля: email, пароль, подтверждение пароля, чекбокс согласия (обязателен).
- Валидация до обращения к БД: `EmailStr` (≤ 254), пароль 8…128, совпадение
  паролей. Ошибки — под полями, форма не перезагружается (HTMX).
- Нормализация email: `strip()` + `lower()`; `+tags` сохраняются (SEC-05).
- `UNIQUE(email)`; занятый адрес → ошибка под полем (осознанно раскрываем факт
  регистрации — SEC-08).
- Успех: создаётся `users` (`consent_at=now()`, `consent_version=CONSENT_VERSION`),
  сессия, редирект на `/`. Подтверждение email не требуется.
- Пароль хешируется Argon2id до вставки; в логи не попадает никогда.

### FR-2. Вход и выход

- `POST /auth/login`: поиск по нормализованному email; при отсутствии
  пользователя выполняется **фиктивная проверка хеша** (защита от оракула по
  времени), затем общее сообщение «Неверный email или пароль».
- Успех: проверка пароля, `check_needs_rehash` → перехеширование, создание
  **новой** сессии (новый токен и CSRF), редирект на `next` или `/`.
- Ограничение `next`: только локальные пути, начинающиеся с `/` (защита от
  open redirect); иначе `/`.
- `POST /auth/logout`: удаляет строку сессии, чистит cookie, редирект `/auth`.
- Выход доступен только с `/profile` (01 UI-13); в меню кнопки нет.

### FR-3. Смена пароля

- `POST /api/profile/password {current_password, new_password, new_password_confirm}` (03 FR-8).
- Проверки: текущий пароль верен (`422 invalid_current_password`), новый
  8…128, новый ≠ текущий, подтверждение совпадает (проверка на клиенте и
  сервере).
- Успех: перехеширование, **все прочие сессии удаляются**, текущая сохраняется,
  CSRF-токен текущей сессии **ротируется** (новый отдаётся в HTML при
  следующем рендере), toast «Пароль изменён».
- Пароль не отображается ни в одном ответе API.

### FR-4. Ручной сброс пароля (CLI)

- Пользователь пишет на `SUPPORT_EMAIL` (значение из конфига, по умолчанию —
  адрес автора проекта).
- Администратор запускает:

```
uv run python scripts/reset_password.py --email user@urfu.ru
```

- Скрипт: находит пользователя (иначе код 1), генерирует пароль из 16 символов
  base58 без похожих (`0/O/1/l`), пишет Argon2-хеш, **отзывает все сессии**,
  печатает пароль один раз в stdout, завершает работу кодом 0.
- Пароль не пишется в логи и в БД в открытом виде; в команду он не передаётся.
- Пользователь входит с новым паролем и меняет его в `/profile`.

### FR-5. Сессии и CSRF

- Сессия: 32 случайных байта (base64url) в cookie, SHA-256 — в БД, TTL 7 дней
  абсолютный (03 CC-04).
- Новая сессия при каждом входе (защита от фиксации); старые сессии не
  продлеваются.
- CSRF-токен создаётся вместе с сессией, передаётся в HTML
  (`<meta name="csrf-token">` + hidden-поле), проверяется сравнением со
  значением в БД. Для `GET/POST /auth/*` до сессии действует анонимный
  double-submit (03 CC-34).
- Ротация CSRF: при входе (новая сессия) и при смене пароля.
- Уборка: `DELETE FROM sessions WHERE expires_at < now()` — при каждом логине и
  раз в сутки фоновой задачей (SEC-07).
- `last_seen_at` обновляется не чаще раза в 5 минут.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` при `COOKIE_SECURE=true`,
  `Path=/`, `Max-Age=7d`. `csrf_token` — без `HttpOnly`.

### FR-6. Защита от перебора

- Счётчик неудачных попыток в памяти процесса по ключу `email + IP`.
- Порог: **5** неудач за **15** минут → блокировка на 15 минут, ответ
  **429** с кодом `too_many_attempts` и `Retry-After`.
- Успешный вход сбрасывает счётчик.
- Пароль проверяется и при блокировке (постоянное время ответа), блокировка
  лишь меняет сообщение.
- Рестарт процесса сбрасывает счётчики — приемлемо для 1–2 пользователей;
  хранение в БД не оправдано.
- Ограничение не распространяется на API (отменённая квота, 03 CC-23).

### FR-7. Пароли

- Argon2id, дефолты `argon2-cffi`: `time_cost=3`, `memory_cost=65536` (64 MiB),
  `parallelism=4`, `hash_len=32`, `salt_len=16` (SEC-04).
- Пароль не обрезается и не нормализуется; лимит 128 символов — защита от DoS.
- Требований к составу (цифры/заглавные) нет — только длина.
- `password_hash varchar(255)`; перехеширование при изменении параметров.

### FR-8. Согласие и ПДн

- Текст правил и обработки ПДн — `app/web/templates/legal/consent.html`,
  открывается в модалке (без отдельного URL).
- Версия — `CONSENT_VERSION="2026-11-25"` в конфиге; при регистрации
  фиксируется `consent_at` + `consent_version`.
- Повторное согласие при смене версии **не запрашивается** (бэклог).
- `/profile` показывает «Согласие получено <дата> (версия X)».
- Собирается только email; пароль — хеш; контент чатов хранится для истории.
- Аналитика, трекеры, сторонние скрипты отсутствуют. Полное соответствие
  152-ФЗ не заявляется (02 FR-9); хостинг — 09.

### FR-9. CLI-управление системой

Всё администрирование — скрипты в `scripts/` (SEC-02):

| Скрипт | Назначение | Код 0 / 1 / 2 |
|---|---|---|
| `ingest.py` | индексация корпуса (04) | успех / есть failed / конфиг |
| `reset_password.py` | сброс пароля | успех / нет пользователя / ошибка конфига |
| `ingest.py --verify` (флаг) | сверка PG ↔ Qdrant ↔ `md/` | чисто / расхождения / ошибка |

- Скрипты читают тот же `.env`, что и приложение; не требуют запущенного
  веб-сервиса, кроме случаев, когда нужен доступ к Qdrant.
- Скрипты идемпотентны и не печатают секреты, кроме явно сгенерированного
  пароля.
- Отдельного «bootstrap-админа» нет: `ADMIN_EMAIL`/`ADMIN_PASSWORD` удаляются
  (D-26), вместо них `SUPPORT_EMAIL`.

### FR-10. Гигиена секретов

- Ключи LLM/embedding — только в `.env`, не в БД, не в UI, не в логах.
- `.env` в `.gitignore`; `.env.example` содержит заглушки.
- `DEBUG=false` в prod: без стектрейсов и SQL в ответах.
- Ошибки не раскрывают существование пользователя (кроме регистрации, SEC-08).
- Логи: `user_id`, `request_id`, код ошибки; email — только как `user_id`.

## 6. Граничные случаи

| Ситуация | Поведение |
|---|---|
| Регистрация без чекбокса | ошибка под чекбоксом, пользователь не создан |
| Пароли не совпали | ошибка под подтверждением |
| Пароль 129 символов | 422 validation_error |
| Email с заглавными | нормализуется, дубликат не создаётся |
| `+tag` в email | отдельный адрес, не склеивается |
| Неверный пароль | общее сообщение, задержка одинаковая |
| Несуществующий email при входе | то же сообщение и время ответа |
| 6-я неудача за 15 минут | 429 `too_many_attempts`, `Retry-After` |
| Успех после 4 неудач | счётчик сброшен |
| Просроченная сессия | 401 JSON / редирект на `/auth?next=…` |
| Смена пароля с неверным текущим | 422 `invalid_current_password`, сессии живы |
| Смена пароля | прочие сессии отозваны, CSRF ротирован |
| Открытый редирект `next=//evil.com` | игнорируется, редирект на `/` |
| Сброс пароля для несуществующего email | код 1, пользователь не создаётся |
| Повторный запуск сброса | новый пароль, старые сессии уже отозваны |
| Пользователь удалён вручную из БД | сессии каскадно удалены, вход невозможен |
| CSRF-токен от старой сессии | 403 `csrf_invalid` |

## 7. НФТ

- **Безопасность:** Argon2id, сессии в БД, CSRF, HttpOnly/SameSite/Secure, 404
  вместо 403, троттлинг входа, отсутствие open redirect.
- **Производительность:** вход ≤ 300 мс на домашнем сервере 12 ядер (Argon2 64 MiB);
  троттлинг не влияет на успешные входы.
- **Приватность:** минимум ПДн, согласие фиксируется, аналитики нет.
- **Эксплуатация:** всё управление — CLI, без скрытых автостартов; скрипты
  идемпотентны.
- **Наблюдаемость:** события входа/смены пароля — в лог (`user_id`, результат),
  без email и паролей.
- **Доступность:** блокировка по IP не должна затрагивать других пользователей
  (ключ `email+IP`, не только IP).

## 8. Критерии приёмки

- [ ] Регистрация невозможна без согласия; после успеха — автовход.
- [ ] Пароль хранится только как Argon2id-хеш; rehash при необходимости.
- [ ] Вход/выход работают; `next` не позволяет внешний редирект.
- [ ] Новая сессия при каждом входе, старая не переиспользуется.
- [ ] Смена пароля отзывает прочие сессии и сохраняет текущую.
- [ ] `scripts/reset_password.py` выдаёт пароль один раз и отзывает сессии.
- [ ] 5 неудач → 429 `too_many_attempts`; успех сбрасывает счётчик.
- [ ] Cookie `sa_session` HttpOnly; CSRF обязателен во всех POST.
- [ ] `consent_at`/`consent_version` заполнены; версия видна в профиле.
- [ ] `ADMIN_*` удалены из конфига, `SUPPORT_EMAIL` используется в модалке.
- [ ] В логах нет email, паролей и текстов сообщений.
- [ ] Просроченные сессии удаляются при логине и раз в сутки.
