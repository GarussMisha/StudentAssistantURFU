## 1. Контекст и цель

База знаний — фундамент продукта: если корпус разобран плохо, никакая настройка
генерации не спасёт. Документ фиксирует путь файла от `data/kb/raw/` до точки в
Qdrant: манифест, конвертацию в канонический Markdown, чанкинг, идентификаторы,
инкрементальную индексацию, удаление и наблюдаемость.

Границы: документ **не** описывает retrieval и генерацию (05), деплой (09) и
eval-датасет (08). Он обязан дать 05 стабильный контракт: «чанк с таким payload
существует и не меняется без переиндексации».

## 4. Функциональные требования

### FR-1. Каталоги и манифест

```
data/kb/
├── raw/          # исходники (вне git): .pdf, .docx, .md
├── md/           # канонический Markdown (вне git, производное)
└── manifest.yaml # декларация состава корпуса (в git)
```

- Структура плоская: подпапки в `raw/` не поддерживаются.
- Манифест (KB-09):

```yaml
version: 1
documents:
  - file: 01_scrum_agile_guide.md
    material_type: book
```

- `material_type ∈ gost | standard | book | article | methodical | other`
  (закрытый список, русские подписи в UI).
- `doc_key` = имя файла без расширения; `title` = первый `# H1` из Markdown,
  иначе имя файла без расширения и без префикса `NN_`.
- Валидация манифеста — Pydantic, `extra="forbid"`: опечатка в ключе роняет
  запуск с кодом 2, а не молча игнорируется.
- Файлы в `raw/`, отсутствующие в манифесте, **игнорируются** с warning.
- Дубликат `file`/`doc_key` в манифесте → код 2.

### FR-2. `kb_documents` — состояние обработки

```sql
CREATE TABLE kb_documents (
    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    doc_key        varchar(120) NOT NULL UNIQUE,
    file           varchar(260) NOT NULL UNIQUE,
    title          varchar(300) NOT NULL,
    material_type  text NOT NULL CHECK (material_type IN
                     ('gost','standard','book','article','methodical','other')),
    source_sha256  bytea       NOT NULL,
    content_sha256 bytea,
    md_path        varchar(300),
    status         text        NOT NULL CHECK (status IN
                     ('pending','converting','chunking','embedding',
                      'indexed','outdated','failed','removed')),
    chunks_count   int         NOT NULL DEFAULT 0,
    source_mtime   timestamptz,
    indexed_at     timestamptz,
    removed_at     timestamptz,
    error_message  text,
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now()
);
```

- `source_sha256` — хеш исходного файла; `content_sha256` — хеш `md/`.
  Решение «переиндексировать» принимается **по хешам**, `source_mtime` хранится
  только для отображения (git-checkout меняет mtime, не меняя содержимое).
- Удалённый из манифеста документ **не удаляется из таблицы**: строка переходит
  в `removed` (KB-15) — так видно, что файл был и что его чанки убраны из индекса.

### FR-3. `kb_chunks` — реестр чанков

```sql
CREATE TABLE kb_chunks (
    id           bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    document_id  bigint NOT NULL REFERENCES kb_documents(id) ON DELETE CASCADE,
    chunk_id     uuid   NOT NULL UNIQUE,     -- = point ID в Qdrant
    chunk_index  int    NOT NULL,            -- порядок внутри документа
    heading_path text   NOT NULL,
    char_count   int    NOT NULL,
    text_sha256  bytea  NOT NULL,
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT uq_kb_chunks_doc_index UNIQUE (document_id, chunk_index)
);
CREATE INDEX ix_kb_chunks_doc ON kb_chunks(document_id);
```

- Текста чанка в PG **нет** (KB-12): источник — `md/` и payload Qdrant.
- Назначение таблицы: знать, из какого файла чанк, уметь точечно удалить его,
  обнаружить устаревание и дубли (`text_sha256`).

### FR-4. Конвертация в Markdown

Модуль `app/rag/convert.py`, диспетчер по расширению:

| Вход | Инструмент | Примечание |
|---|---|---|
| `.md` | без конвертации | копируется в `md/` |
| `.docx` | `markitdown` | заголовки Docx сохраняются |
| `.pdf` | `pymupdf4llm` | сохраняет заголовки и таблицы |
| `.pdf` (fallback) | `markitdown` | если `pymupdf4llm` бросил исключение |

- Итог: `data/kb/md/<doc_key>.md` (UTF-8, LF), перезапись при каждом ingest.
- Если после конвертации текст < **200 символов** → `failed`,
  `error_message = "не извлечён текст (возможно, скан)"`. OCR не делаем (KB-08).
- Неподдерживаемое расширение в манифесте → `failed` на документе, остальные
  обрабатываются.

### FR-5. Нормализация и таблицы → HTML

1. Приведение к LF, удаление trailing spaces, схлопывание 3+ пустых строк до 2.
2. Блоки кода (```) **защищаются** от любых преобразований.
3. Markdown pipe-таблицы конвертируются в HTML:

```html
<table><thead><tr><th>…</th></tr></thead>
<tbody><tr><td>…</td></tr></tbody></table>
```

- Содержимое ячеек экранируется (`&`, `<`, `>`, `"`).
- Таблица определяется как ≥ 2 строк с `|` подряд плюс строка-разделитель
  `|---|`. Если разбор не удался — таблица остаётся Markdown, в лог пишется
  warning, документ индексируется (KB-16).
- Уже существующие HTML-таблицы (если конвертер их выдал) не трогаем.

### FR-6. Чанкинг

Параметры (KB-10, KB-11), в `Settings` с дефолтами:
`CHUNK_TARGET=600`, `CHUNK_MAX=900`, `CHUNK_MIN=150`, `CHUNK_OVERLAP=90`,
`CHUNK_ABSOLUTE_MAX=3000`.

Алгоритм:

1. Разбор по заголовкам `#…######`; `heading_path` = стек заголовков через ` > `,
   корень — `title` документа. Заголовок не входит в текст чанка, но входит в
   `heading_path`.
2. Атомарные блоки: HTML-таблица, fenced code, цитата-блок. Не дробятся.
3. Остальной текст пакуется абзацами до **600**; при превышении **900** — разрез.
4. Разрез — по последнему пробелу, отклонение от цели **≤ 20 символов**
   (600…620). Слово, не влезающее в 900, переносится целиком; слово длиннее
   900 — режется посимвольно (патология, warning).
5. Перекрытие **90 символов** от конца предыдущего чанка, выравнивается по
   границе слова (≤ 20 символов регулировки); входит в лимит 900.
6. Чанк короче **150** приклеивается к предыдущему в той же секции; если
   предыдущего нет — остаётся как есть.
7. Атомарный блок больше **3000** символов: таблица режется по строкам с
   повтором `<thead>`, код — по строкам; каждый кусок ≤ 3000 (KB-10).
8. Пустые чанки и чанки из одних пробелов не создаются.

### FR-7. `chunk_id` и payload

- `chunk_id = uuid5(NAMESPACE_DOC, f"{doc_key}|{heading_path}|{chunk_index}|{text_sha256_hex}")`
  (KB-06) — детерминирован, стабилен при неизменном тексте, валиден как point ID.
- Payload Qdrant:

```json
{"doc_key": "01_scrum_agile_guide", "document_title": "Scrum Guide",
 "material_type": "book", "heading_path": "Scrum Guide > Роли",
 "chunk_index": 3, "text": "…", "source_file": "01_scrum_agile_guide.md"}
```

- `text` дублируется в payload: цитата (03 §FR-4) не требует чтения `md/` в
  рантайме.
- Эмбеддинг считается от `"{document_title} > {heading_path}\n{text}"`, а в
  payload хранится «чистый» `text` (KB-17) — заголовок помогает retrieval, но не
  засоряет цитату.

### FR-8. Индексация

- Коллекция `kb_chunks`: `distance=Cosine`, размерность — из первого вектора,
  `on_disk_payload=true`. Существующая коллекция другой размерности → выход с
  кодом **2** и сообщением «сменилась модель эмбеддингов, пересоздайте коллекцию
  флагом `--recreate-collection`».
- Батчи по **32** чанка; retry 3× с задержкой 1/2/4 с на 429 и 5xx; таймаут
  `EMBEDDING_TIMEOUT_SECONDS=60`.
- Порядок на документ: эмбеддинги → `DELETE` старых точек по фильтру
  `doc_key` → upsert новых → одна транзакция PG (строки `kb_chunks` +
  `chunks_count` + статус). При сбое — `failed`; «хвосты» в Qdrant убирает
  верификация следующего запуска.

### FR-9. Инкрементальность, дедупликация, удаление

Решение по каждому документу (KB-07):

| Состояние | Действие |
|---|---|
| нет строки в PG | полная обработка |
| `source_sha256` совпал, `status=indexed`, `md/` на месте | **skip** |
| `source_sha256` совпал, `status=failed` | повторная попытка |
| `source_sha256` изменился, `content_sha256` совпал | обновить хеши, чанки не трогать |
| `content_sha256` изменился | полная переиндексация |
| `md/` отсутствует | конвертация заново |
| `status=removed`, файл вернулся в манифест | полная обработка |
| `--force` | полная обработка всегда |

- **Дубликат файла:** одинаковый `source_sha256` у двух `doc_key` → документ с
  алфавитно меньшим `doc_key` индексируется, остальные `failed`
  (`"дубликат файла <doc_key>"`). Детерминированно, без «кто первый встал».
- **Дубликат чанка:** одинаковый `text_sha256` внутри документа → последующие
  отбрасываются (колонтитулы, повторяющиеся блоки).
- **Удаление:** документ исчез из манифеста → `DELETE` точек по `doc_key`,
  `DELETE kb_chunks`, строка → `removed`, `chunks_count=0`, `removed_at=now()`
  (KB-15).
- **Сироты в `md/`** (нет в манифесте) → файл удаляется с warning.
- **Сироты в Qdrant** (точка с `doc_key`, которого нет среди `indexed`) →
  удаляются в конце прогона (сверка, не «починка»).

### FR-10. Статусы и CLI

Статусы: `pending → converting → chunking → embedding → indexed`, а также
`outdated`, `failed`, `removed`. Переходы пишутся в БД для наблюдаемости.

```
uv run python scripts/ingest.py [--doc <doc_key>] [--force]
                                [--dry-run] [--verify]
                                [--recreate-collection]
```

| Флаг | Действие |
|---|---|
| `--doc` | только один документ |
| `--force` | игнорировать хеши |
| `--dry-run` | конвертация и чанкинг без записи в PG/Qdrant, печать статистики |
| `--verify` | сверка PG ↔ Qdrant ↔ `md/`, ничего не изменяет |
| `--recreate-collection` | удалить и создать коллекцию заново (смена модели) |

- **Автоиндексации при старте приложения нет** (KB-07): рестарт контейнера не
  должен тратить эмбеддинги.
- Коды возврата: `0` — все `indexed`/skip; `1` — есть `failed`; `2` — конфиг,
  манифест, БД или несовпадение размерности.
- Итоговый отчёт в stdout: таблица `doc_key | статус | чанков | время | причина`.

### FR-11. Наблюдаемость

- `structlog`, по документу: `doc_key, status, chunks, duration_ms, error`;
  **текст чанков не логируется** (только длины и хеши).
- `/health` (03 §FR-10): `kb.documents = COUNT(status='indexed')`,
  `kb.chunks = SUM(chunks_count)`, `kb.indexed_at = MAX(indexed_at)`;
  `empty` — нет строк; `not_indexed` — есть строки, но 0 indexed;
  `degraded` — есть `failed`/`outdated`.

## 5. Контракты и точки интеграции

| Потребитель | Что получает | Гарантия |

## 6. Граничные случаи

| Ситуация | Поведение |
|---|---|
| Пустой `raw/` | код 2, «корпус пуст» (не «успешно 0») |
| Нет манифеста | код 2 |
| Опечатка в ключе манифеста | код 2 (Pydantic `extra=forbid`) |
| Файл из манифеста отсутствует в `raw/` | `failed`, остальные обрабатываются |
| PDF-скан без текста | `failed`, «не извлечён текст» |
| PDF с битой кодировкой | fallback markitdown, затем `failed` |
| Таблица > 3000 | дробление по строкам с повтором `<thead>` |
| Таблица не распарсилась | остаётся Markdown, warning, индексация продолжается |
| Файл-дубликат (тот же sha256) | один `indexed`, остальные `failed` |
| Повторный ingest без изменений | все skip, 0 вызовов эмбеддингов |
| Изменён только mtime | skip (решают хеши) |
| Документ удалён из манифеста | `removed`, точки и `kb_chunks` удалены |
| Файл вернулся после удаления | полная обработка, строка переиспользуется |
| Смена модели эмбеддингов | код 2, инструкция `--recreate-collection` |
| Обрыв сети при эмбеддингах | 3 retry, затем `failed`, прогон продолжается |
| Кириллица в именах файлов | `doc_key` транслитерируется? **нет** — только латиница/цифры/дефис, иначе код 2 |

## 7. НФТ

- **Скорость:** 3 пилотных файла — ≤ 60 с на локальной модели; 40 документов —
  ≤ 10 мин; повторный прогон без изменений — ≤ 5 с (0 эмбеддингов).
- **Идемпотентность:** любой прогон можно повторять без дублей и потери данных.
- **Устойчивость:** падение одного документа не останавливает остальные; БД и
  Qdrant не остаются в «полузаписанном» виде незаметно — `--verify` показывает
  расхождения.
- **Ресурсы:** память ≤ 512 МБ на ингест; файлы читаются по одному, не все сразу.
- **Приватность:** корпус и `md/` — вне git; в логи не попадает текст.
- **Воспроизводимость:** `manifest.yaml` + `content_sha256` + имя модели
  эмбеддингов достаточно, чтобы повторить индекс.

## 8. Критерии приёмки

- [ ] Манифест с 3 пилотными файлами валиден; лишний файл в `raw/` игнорируется.
- [ ] Все 3 файла превращены в `data/kb/md/*.md`, таблицы — HTML, текст читаем.
- [ ] Чанки: 150 ≤ длина ≤ 900, кроме атомарных блоков (≤ 3000); перекрытие 90;
      разрез не по середине слова.
- [ ] `kb_chunks.chunk_id` совпадает с point ID в Qdrant, `chunks_count` = числу
      точек по `doc_key`.
- [ ] Повторный ingest без изменений: 0 эмбеддингов, все skip, ≤ 5 с.
- [ ] Изменение файла → переиндексация только этого документа.
- [ ] Удаление из манифеста → `removed`, точки и `kb_chunks` удалены, `md/`
      почищен.
- [ ] Дубликат файла → `failed` с указанием первичного `doc_key`.
- [ ] Скан-PDF → `failed`, `/health` → `degraded`.
- [ ] Смена модели эмбеддингов → код 2 с понятной инструкцией.
- [ ] `--dry-run` не пишет ни в PG, ни в Qdrant; `--verify` находит искусственно
      удалённую точку.
- [ ] `data/kb/raw` и `data/kb/md` видны в контейнере (bind-mount, F-06).
