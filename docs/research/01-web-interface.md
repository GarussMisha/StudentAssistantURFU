# 01. Исследование: веб-интерфейс «URFU Agent»

- Статус: СОГЛАСОВАНО (v1.1); частичная ревизия по дельтам D-01…D-04 из 02;
  пункты, помеченные ⚠️, финализируются в 03 после закрытия OQ-01
- Дата: 2026-11-22 (v1.1 — тот же день)
- Связанные: 03 (контракты), 06 (чаты/оценки), 07 (аккаунты)

## 1. Контекст и цель

RAG-ассистент для студентов УРФУ по проектной деятельности. Веб-интерфейс —
витрина продукта: чат с цитатами, история, аккаунт. Стек зафиксирован:
Jinja2 + HTMX + SSE, серверный рендеринг, без SPA и сборки фронтенда.
Реализация — M2–M3.

## 2. Пользователи и ключевые сценарии

- Новый: `/` → `/auth` → «Регистрация» → `/` → новый чат.
- Возвращающийся: `/` → `/auth` → `/` → выбрать чат в меню.
- Вопрос: ввод → SSE-ответ → источники → оценка.
- Сбой сервиса: toast + вопрос сохраняется + повтор.
- Забыл пароль: `/auth` → модалка → письмо администратору.

## 3. Карта страниц

/auth — вкладки «Вход» / «Регистрация» (только гости)
/     — меню + чат (требует сессии)
/profile — профиль, смена пароля, удаление истории, выход (требует сессии)

Неавторизованный доступ к `/` и `/profile` → `/auth?next=<path>`.
Авторизованный на `/auth` → `/`.

## 4. FR-1. `/auth`

- Две вкладки; переключение меняет секцию полей без перезагрузки (HTMX).
- Поля входа: email, пароль. Регистрации: email, пароль, подтверждение.
- В регистрации — обязательный чекбокс «Согласен с правилами проекта и
  обработкой ПДн»; ссылка открывает модалку с текстом правил; без него
  отправка невозможна (D-01 из 02).
- Валидация: email по формату; пароль ≥ 8 символов; ошибки под полями;
  несовпадение паролей — под подтверждением; занятый email — под email;
  неверные учётные данные — общее сообщение над формой.
- Успешная регистрация сразу логинит → `/`.
- «Забыли пароль?» → модалка: написать с той же почты на garussm@gmail.com;
  администратор вышлет новый пароль; кнопка «Скопировать адрес».

## 5. FR-2. Menu (слева, сворачиваемое)

Сверху вниз:
1. Логотип «URFU Agent» (текстовый, цветовое выделение).
2. Кнопка поиска → модалка «Функционал в разработке».
3. Кнопка «Свернуть/Развернуть».
4. «Новый чат» → создаёт пустой чат, открывает `/`.
5. Список чатов: до 15, ленивая подгрузка; группы «Сегодня», «Вчера»,
   «На этой неделе», «В этом месяце», «Ранее»; заголовок = первый вопрос
   (~50 символов, ellipsis); активный чат подсвечен; без времени и сниппетов.
6. Внизу: аватар (круг с первой буквой email) + email → `/profile`.

Свёрнутое меню — полоса ~48px, только кнопка «Развернуть». Состояние
в localStorage. Мобильно: шторка с затемнением, закрыта по умолчанию,
бургер в верхней полосе; чат на всю ширину.

Пусто: «Пока нет чатов. Начните новый».
Ошибка списка: «Не удалось загрузить, повторить».

## 6. FR-3. Чат

- Стартовый экран: приветствие, «Отвечает только по загруженной базе знаний»,
  3 примера вопросов; клик вставляет текст в поле (не отправляет).
- Сообщения: пользователь — справа (текст экранируется); ассистент — слева,
  Markdown → безопасный HTML (списки, таблицы, код); таблицы со скроллом.
- Ввод: textarea с автовысотой; Enter — отправить, Shift+Enter — перенос;
  пустой вопрос не отправляется; во время генерации отправка заблокирована.
- Поток SSE: поле очищается сразу, пузырь пользователя мгновенно, ответ
  дорисовывается; при сбое вопрос возвращается в поле, toast «Повторить».
- Цитаты: маркеры [1]…[n] в тексте, нумерация в каждом ответе заново;
  под ответом список источников; клик по маркеру — скролл + раскрытие +
  подсветка; в раскрытии: название документа, тип материала,
  heading_path, фрагмент.
- Действия под ответом: «Скопировать» (исходный Markdown ответа, toast),
  «Лайк»/«Дизлайк» (сохраняются сразу), при любом нажатии рядом появляется
  поле «Дайте комментарий» + «Отправить» (комментарий опционален).
  Оценка восстанавливается после перезагрузки и может быть изменена.
- Ответ без БЗ (`ungrounded`): явное предупреждение, что ответ опирается на
  общие знания модели и не основан на базе знаний проекта; цитат нет; это
  обычное сообщение ассистента, не ошибка (D-02 из 02).
- Пустая база ⚠️: по текущей спеке — сообщение, отправка заблокирована,
  после индексации оживает без перезапуска; поведение может замениться
  ungrounded-режимом по решению OQ-01 (→ 03, D-04).

## 7. FR-4. `/profile`

- Блок профиля: аватар-буква, email, дата регистрации, число чатов.
- Смена пароля: текущий / новый / подтверждение; ошибки под полями;
  успех — toast; текущая сессия сохраняется, остальные отзываются.
- «Удалить всю историю чатов» → модалка с чекбоксом «Я понимаю, что
  восстановить нельзя»; после — меню очищено, редирект на `/`, toast.
- «Выйти» (единственное место выхода).

## 8. Сквозные состояния и элементы

- Toast top-right, автоскрытие ~5 c: ошибки сервиса, успехи.
- Единая модалка «Функционал в разработке» для всех заглушек.
- Скелетоны при загрузке списка чатов и истории сообщений.
- Ошибка сервиса: проверка при загрузке `/` и перед отправкой; toast с
  «Проверить снова»/«Повторить»; поле не блокируется; в чате ошибка не
  дублируется.
- 401 → `/auth?next=...`.
- Таймстемпы сообщений не показываем.

## 9. Контракты, которые UI ожидает от бэкенда

- `GET /` — оболочка чата + состояние health.
- `GET /api/chats?limit=15&cursor=...` — чаты: id, title, created_at,
  updated_at; сортировка по активности.
- `POST /api/chats` — создать чат.
- `GET /api/chats/{id}/messages` — сообщения в порядке отправки.
- `POST /api/chats/{id}/messages` — SSE-стрим: события
  `meta {message_id}`, `delta {text}`, `sources {items[]}`,
  `done {status: grounded|ungrounded|no_answer}` ⚠️ (D-03 из 02; окончательная
  семантика и транспортный `error` — в 03), `error {code, message}`.
- Источник: `source_no`, `chunk_id`, `document_title`, `material_type`,
  `heading_path`, `snippet`.
- `POST /api/messages/{id}/rating {value: like|dislike}`;
  `POST /api/messages/{id}/comment {text}`.
- `POST /api/profile/password`, `POST /api/profile/history/delete`.
- `POST /auth/logout`, `GET /health`.

## 11. Сквозные НФТ интерфейса

- Mobile-first, брейкпоинт ~768px; детальная доводка — бэклог.
- Доступность: labels, фокус, контраст ≥ 4.5:1, ARIA у модалок/toast.
- Без CDN: все ассеты локальные.
- Безопасность: CSRF во всех POST, HttpOnly/SameSite, санитайзинг HTML.
- Производительность: первый чанк без ожидания полного ответа.

## 12. Граничные случаи

- Пустой вопрос; двойной клик; Enter в пустом поле.
- Обрыв SSE → частичный ответ, повтор.
- Длинные заголовки, ответы, таблицы.
- HTML/скрипты в пользовательском тексте — экранируются.
- Удаление истории при открытом чате → `/`.
- Clipboard API недоступен → fallback через textarea.
- Неверный текущий пароль при смене.
