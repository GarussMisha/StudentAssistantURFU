# Spec Delta

## Purpose

Сохраняет диалоги пользователя, позволяет возвращаться к ним, искать по истории и оценивать качество ответов, не раскрывая данные других пользователей.

## ADDED Requirements

### Requirement: Создание чата

Аутентифицированный пользователь SHALL иметь возможность создать чат. Чат SHALL принадлежать создавшему пользователю, иметь заголовок и время последней активности. Если заголовок не задан, он SHALL формироваться из первого вопроса пользователя с ограничением длины.

#### Scenario: Чат без заголовка получает значение по умолчанию

- **WHEN** пользователь создаёт чат, не указывая заголовок
- **THEN** чат получает заголовок по умолчанию

#### Scenario: Первый вопрос формирует заголовок

- **WHEN** пользователь отправляет первый вопрос в новый чат
- **THEN** заголовок чата формируется из вопроса с ограничением длины

#### Scenario: Чат доступен только создателю

- **WHEN** чат создан
- **THEN** он доступен только создавшему его пользователю

### Requirement: Сохранение сообщений и результатов ответа

Каждое сообщение пользователя и ассистента SHALL сохраняться с ролью, текстом, временем и порядковым номером. Для ответа ассистента SHALL сохраняться статус (`answered`, `refused`, `degraded`) и цитаты. Сообщение пользователя SHALL сохраняться даже при ошибке генерации.

#### Scenario: Успешный обмен сохраняется в порядке отправки

- **WHEN** обмен вопросом и ответом завершён
- **THEN** вопрос и ответ сохранены в порядке отправки с временными метками

#### Scenario: Отказ сохраняется как ответ

- **WHEN** генерация завершилась отказом
- **THEN** ответ сохранён со статусом `refused`

#### Scenario: Ошибка не теряет вопрос

- **WHEN** генерация завершилась ошибкой
- **THEN** вопрос сохранён, а ответ помечен статусом `degraded`

### Requirement: Список чатов пользователя

Пользователь SHALL видеть список только своих чатов, упорядоченный по времени последней активности. Каждый элемент SHALL содержать заголовок, фрагмент последнего сообщения и время. Список SHALL поддерживать постраничную выдачу.

#### Scenario: Пользователи видят только свои чаты

- **WHEN** у двух пользователей есть чаты
- **THEN** каждый видит только собственные чаты

#### Scenario: Новое сообщение поднимает чат в списке

- **WHEN** в чате появляется новое сообщение
- **THEN** чат перемещается в начало списка

#### Scenario: Длинный список листается

- **WHEN** чатов больше размера страницы
- **THEN** доступна следующая страница списка

### Requirement: Продолжение диалога

При открытии чата система SHALL восстанавливать все сообщения в исходном порядке и позволять продолжить диалог. Контекст последних сообщений SHALL передаваться в RAG-пайплайн для переформулировки запроса.

#### Scenario: История восстанавливается в исходном порядке

- **WHEN** пользователь открывает ранее созданный чат
- **THEN** история отображается в порядке отправки сообщений

#### Scenario: Диалог продолжается после перезапуска

- **WHEN** пользователь продолжает диалог после перезапуска приложения
- **THEN** новый ответ учитывает предыдущие сообщения чата

### Requirement: Поиск по истории

Система SHALL искать по тексту сообщений и заголовкам чатов только в пределах чатов текущего пользователя. Поиск SHALL быть регистронезависимым, возвращать чат, фрагмент совпадения и позволять перейти к найденному сообщению. Пустой результат SHALL отображаться явным сообщением.

#### Scenario: Совпадение в своём чате находится

- **WHEN** пользователь ищет слово, встречающееся в его сообщении
- **THEN** результат содержит чат и фрагмент с совпадением

#### Scenario: Пустой результат явно показывается

- **WHEN** совпадений нет
- **THEN** интерфейс сообщает об отсутствии результатов

#### Scenario: Чужие сообщения не попадают в поиск

- **WHEN** искомый текст есть только в чате другого пользователя
- **THEN** результат не возвращается

### Requirement: Оценка ответа

Пользователь SHALL иметь возможность оценить ответ ассистента как полезный или неполезный и при желании добавить комментарий. На одно сообщение SHALL приходиться не более одной оценки пользователя; повторная оценка SHALL заменять предыдущую. Оценка SHALL сохраняться и отображаться после перезагрузки.

#### Scenario: Оценка сохраняется

- **WHEN** пользователь ставит оценку ответу
- **THEN** она сохраняется и видна после перезагрузки страницы

#### Scenario: Повторная оценка заменяет предыдущую

- **WHEN** пользователь меняет оценку того же ответа
- **THEN** сохраняется новое значение, а дубликат оценки не создаётся

#### Scenario: Чужой ответ нельзя оценить

- **WHEN** пользователь пытается оценить ответ в чужом чате
- **THEN** операция отклоняется

### Requirement: Изоляция доступа к истории

Любая операция с чатом, сообщением, поиском или оценкой SHALL требовать аутентификации и проверять владельца. При обращении к чужому ресурсу система SHALL не раскрывать его существование.

#### Scenario: Неаутентифицированный пользователь перенаправляется на вход

- **WHEN** неаутентифицированный пользователь открывает чат
- **THEN** он перенаправляется на страницу входа

#### Scenario: Чужой чат не раскрывается

- **WHEN** пользователь запрашивает чужой чат по идентификатору
- **THEN** возвращается ошибка доступа без данных чата

#### Scenario: Поиск ограничен владельцем

- **WHEN** пользователь ищет по истории
- **THEN** поиск выполняется только по его чатам
