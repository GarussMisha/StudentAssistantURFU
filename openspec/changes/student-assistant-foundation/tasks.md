# Tasks

Реализация идёт вертикальными срезами M0–M5 из `design.md`. Домен и хостинг остаются параметрами развёртывания: в Caddyfile и `.env` используется placeholder, конкретный домен выбирается в задаче 8.3. Админ-UI не входит в спецификации этого change; повторная индексация доступна через CLI.

## 1. Основа и среда выполнения

- [ ] 1.1 Заполнить `Dockerfile` для Python 3.14 и `uv`, обновить `.dockerignore`; проверить, что `docker build -t student-assistant .` завершается успешно и контейнер импортирует `app.main`.
- [ ] 1.2 Создать пакеты `app/api`, `app/db`, `app/rag`, `app/schemas`, `app/services`, `app/web` с `__init__.py` и базовым app factory; проверить командой `uv run python -c "from app.main import app; print(app.title)"`.
- [ ] 1.3 Расширить `Settings`: коллекция Qdrant, размеры чанков и перекрытие, top-k и порог retrieval, таймауты LLM и эмбеддингов, TTL сессии, лимиты, CSRF-секрет, пути eval; проверить тестами `tests/core/test_config.py` на значения по умолчанию и переопределение из env.
- [ ] 1.4 Настроить async SQLAlchemy engine, фабрику сессий и Alembic; проверить `uv run alembic upgrade head` и `uv run alembic downgrade base` на пустой PostgreSQL.
- [ ] 1.5 Реализовать `/health` с проверкой PostgreSQL, Qdrant и состояния базы знаний; проверить тестами на `ok` и `degraded` и вручную через `curl http://localhost:8000/health`.
- [ ] 1.6 Добавить pytest-фикстуры для тестовой БД, фейковых LLM/эмбеддингов и Qdrant-заглушки; проверить, что пример теста проходит без внешней сети командой `uv run pytest -q`.
- [ ] 1.7 Обновить `README.md`: локальный запуск, переменные `.env`, структура пакетов; проверить, что описанные команды выполняются как написано.

## 3. RAG-ответы (M1)

- [ ] 3.1 Реализовать retrieval-сервис: эмбеддинг запроса, поиск top-k в Qdrant, фильтр по порогу, возврат чанков с метаданными; проверить тестами на пустую выдачу, выдачу ниже порога и релевантные чанки.
- [ ] 3.2 Реализовать переформулировку запроса по последним 3–5 сообщениям с fallback на объединение вопросов; проверить тестами уточняющий вопрос, недоступный rewrite и первый ход диалога.
- [ ] 3.3 Реализовать сборку промпта и клиент LLM: ответ только по контексту, формат цитат, инструкция отказа; проверить тестами, что в контекст попадают только найденные чанки и нет внешних фактов.
- [ ] 3.4 Реализовать пайплайн ответа: обязательный retrieval, генерация, проверка цитат по выданным чанкам, отказ при низкой релевантности; проверить интеграционными тестами с фейковыми LLM, эмбеддингами и Qdrant.
- [ ] 3.5 Добавить обработку деградации LLM и эмбеддингов и сценарии multi-turn; проверить тестами, что ошибка сервиса отличается от отказа, вопрос сохраняется, а прежние ответы не становятся источником фактов.
- [ ] 3.6 Довести корпус до 10 документов, обновить манифест и переиндексировать; проверить, что все 10 документов имеют статус `indexed`, а покрытие вопросов достигает трёх на документ.
- [ ] 3.7 Пройти M1-приёмку: 10 вопросов по базе и 3 вопроса вне базы; проверить не менее 8 ответов с корректными цитатами и 3 отказа, зафиксировать результат в `eval/m1_smoke.md` и описать RAG-пайплайн в `README.md`.

- [ ] 4.2 Реализовать Argon2id-хеширование и проверку пароля, политику не менее 8 символов; проверить тестами отсутствие открытого пароля, разные хеши для одинаковых паролей и отказ для короткого пароля.
- [ ] 4.3 Реализовать регистрацию с нормализацией email, подтверждением пароля и обработкой занятого email; проверить тестами успешную регистрацию, дубликат в другом регистре и несовпадение паролей.
- [ ] 4.4 Реализовать вход и выход: серверная сессия, HttpOnly-cookie с SameSite=Lax и Secure в продакшене, удаление сессии при выходе; проверить тестами общее сообщение об ошибке для неверного email и пароля и неработоспособность старого токена.
- [ ] 4.5 Реализовать зависимость аутентификации с проверкой существования и срока сессии; проверить тестами доступ владельца, отказ для истёкшей и отозванной сессии.
- [ ] 4.6 Добавить CSRF-защиту изменяющих запросов и ограничение неудачных попыток входа и регистрации; проверить тестами запрос без токена, превышение лимита и сброс счётчика после успешного входа.
- [ ] 4.7 Описать модель угроз и настройки безопасности в `README.md`; проверить, что описанные cookie-атрибуты, TTL и лимиты совпадают с конфигурацией и тестами.
