## 2. Стек и обоснование

| Слой | Выбор | Почему |
|------|-------|--------|
| Язык | Python 3.14.9 | Экосистема RAG/эмбеддингов, требование курса; 3.15 не подходит из-за `markitdown` и `onnxruntime` |
| Web | FastAPI + Uvicorn | Асинхронный стриминг, автодокументация, минимум магии |
| UI | Jinja2 + HTMX + Alpine.js + Tailwind | Серверный рендеринг без SPA; HTMX даёт SSE и частичные обновления |
| LLM | Универсальный LLM Gateway (OpenAI-совместимый): LM Studio `127.0.0.1:1234` (dev) или OpenRouter (prod) | Один код для двух режимов, переключение конфигом |
| LLM-обвязка | LangChain (`langchain-openai`, `langchain-core`) | Промпты, история, стриминг |
| Конвертация в MD | MarkItDown (PDF, DOCX, HTML) + `pymupdf4llm==1.28.2` как fallback для сложных PDF | Один канонический формат для чанкинга и цитат. Версия `pymupdf4llm` пинована: 2.0 на PyPI — пустой метапакет без кода (проверено 2026-10-24) |
| Чанкинг | LangChain `MarkdownHeaderTextSplitter` + `RecursiveCharacterTextSplitter` | Режем по структуре Markdown, а не по символам |
| Эмбеддинги | `text-embedding-qwen3-embedding-0.6b` через OpenAI-совместимый `/v1/embeddings` | Локально в dev, внешний провайдер в prod; приложение не грузит модель |
| Sparse-поиск | FastEmbed `Qdrant/bm25` | Гибридный поиск без Elasticsearch |
| Векторная БД | Qdrant | Нативный hybrid search + RRF, алиасы коллекций |
| Реляционная БД | PostgreSQL 16 + SQLAlchemy 2 (async) + Alembic | Источник истины, миграции |
| Auth | Argon2id + серверные сессии | Отзыв сессий, нет JWT-секрета |
| Файлы | Локальный volume `/data/kb/{raw,md}` | Корпус не в git, только на сервере |
| Конфиг | pydantic-settings + `.env` | Валидация на старте, секреты вне git |
| Логи | structlog (JSON, обезличенные) | Разбор по `request_id` без привязки к личности |
| Тесты | pytest, pytest-asyncio, httpx, respx | Мок LLM без трат лимита |
| Деплой | Docker Compose + Caddy на Ubuntu | Авто-TLS, один сервер |
| CI | GitHub Actions | ruff + pytest на каждый push |

Полные сравнения альтернатив — в `research.md`.

## 3. Архитектура и интеграции

Схемы: `architecture.md`.

**Границы компонентов:**

| Компонент | Ответственность | Не отвечает за | Спека |
|-----------|-----------------|----------------|-------|
| Ingestion | Приём файла, конвертация в MD, чанкинг, эмбеддинги, версии индекса | Поиск, генерацию | 001 |
| RAG Orchestrator | Переформулировка запроса, retrieval, сборка контекста, промпт, цитаты | HTTP, хранение диалогов | 002 |
| LLM / Embedding Gateway | Выбор провайдера, ретраи, таймауты, учёт токенов | Смысл промпта | 002 |
| Backend/API | Регистрация, сессии, диалоги, фидбек, права доступа | Логику поиска | 003 |
| Admin | Страница управления: документы, статусы, индексация, пользователи, сброс пароля | Контент БЗ | 003 |
| Web UI | Чат, стриминг, источники, история, формы | Бизнес-логику | 004 |
| Evaluation | Golden set, метрики, отчёт | Рантайм сервиса | 005 |
| Ops | Compose, TLS, бэкапы, мониторинг | Прикладной код | 006 |

**Ключевые решения (ADR):**
1. PostgreSQL — источник истины, Qdrant — производный индекс.
2. Markdown — каноническое представление документа: конвертация один раз, дальше
   чанкинг, цитаты и просмотр работают с одним форматом.
3. Blue/green коллекции Qdrant через алиас — переиндексация без простоя.
4. LLM и эмбеддинги — внешние API. Приложение не держит модели в памяти: на VPS
   только app, PostgreSQL и Qdrant.
5. Гибридный поиск dense + BM25 + RRF — точные термины и аббревиатуры.
6. LangChain только для LLM/промптов/сплиттеров; retrieval — через `qdrant-client`.
7. Серверные сессии вместо JWT.
8. Jinja2 + HTMX вместо SPA.
9. Провайдер и модель LLM — конфиг, выбор по eval.
10. Универсальный шлюз на OpenAI-протоколе: dev local, prod remote, код один.
11. Администратор создаётся при старте из env; сброс пароля — только админом.

## 4. Модель данных (обзор)

Детализация и DDL — в спеке 003 (`data-model.md`).

| Сущность | Назначение | Ключевые поля |
|----------|------------|---------------|
| `users` | Пользователи | id, email (unique), password_hash, is_admin, created_at, password_changed_at |
| `auth_sessions` | Серверные сессии | id, user_id, token_hash, expires_at, last_seen_at, revoked_at |
| `conversations` | Диалоги | id, user_id, title, created_at, updated_at, archived |
| `messages` | Сообщения | id, conversation_id, role, content, model, latency_ms, tokens_in/out, meta (JSONB) |
| `message_sources` | Цитаты ответа | message_id, chunk_id, rank, score |
| `feedback` | Оценки | id, message_id, user_id, rating, reason, comment, created_at |
| `documents` | Документы БЗ | id, title, author, year, source_type, source_format, raw_path, markdown_path, checksum, status, version, meta (JSONB) |
| `chunks` | Фрагменты (истина) | id, document_id, ordinal, heading_path, page, text, token_count, qdrant_point_id |
| `ingestion_jobs` | Запуски индексации | id, status, total, processed, started_at, finished_at, stats (JSONB), error |

Связи: `users 1—N conversations 1—N messages 1—N message_sources N—1 chunks N—1 documents`.
Удаление диалога — каскадное; удаление документа — каскадное с удалением точек в Qdrant.

**SSE-события ответа:**

```
event: token    data: {"text": "..."}
event: sources  data: {"items": [{"chunk_id": "...", "document": "...", "section": "...", "page": 12, "score": 0.81}]}
event: done     data: {"message_id": "...", "latency_ms": 4210, "model": "..."}
event: error    data: {"code": "llm_unavailable", "message": "..."}
```

**Ошибки API** — единый формат `{"error": {"code": "...", "message": "..."}}`.

**Конфигурация** (`app/core/config.py`): `DATABASE_URL`, `QDRANT_URL`,
`LLM_PROVIDER` (`openrouter|local`), `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`,
`LLM_FALLBACK_MODELS`, `EMBEDDING_BASE_URL`, `EMBEDDING_API_KEY`, `EMBEDDING_MODEL`,
`EMBEDDING_DIM=1024`, `RETRIEVAL_TOP_K`, `RELEVANCE_THRESHOLD`, `SESSION_TTL_DAYS`,
`RATE_LIMIT_PER_HOUR`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `KB_DATA_DIR`, `MAX_UPLOAD_MB`.

Провайдер LLM выбирается **только конфигом**. Для local-режима в Docker адрес хоста
не `127.0.0.1`: Windows/macOS — `host.docker.internal`, Linux bridge — `172.17.0.1`
(подробно — `architecture.md` §8).

## 6. Риски и снижение

| Риск | Вер. | Влияние | Что делаем |
|------|------|---------|------------|
| Корпус БЗ не готов к началу разработки | Высокая | Блокирует eval и демо | Seed-корпус из открытых документов; golden set пишем по темам, источники проставляем после поставки; срок и ответственный зафиксированы |
| В корпусе окажутся сканы без текстового слоя | Средняя | Часть БЗ не индексируется | Договориться с Деменко о формате; детект пустого текста → `failed` с причиной; OCR — отдельное решение |
| Провайдер эмбеддингов для прода не определён (OpenRouter embeddings не отдаёт) | Высокая | Нет прода без локальной модели | Spike: LM Studio на отдельном хосте, Jina/Cohere, GigaChat embeddings; интерфейс `/v1/embeddings` уже универсален |
| Локальная LLM медленная или слабая | Средняя | Демо затягивается | Модели 3–8B, лимит `max_tokens`, замер latency, eval на двух конфигурациях |
| Суточные лимиты free-моделей OpenRouter | Средняя | Блокирует прогоны eval | Dev и eval — на локальной модели; remote включаем на приёмке |
| `127.0.0.1:1234` недоступен из контейнера | Средняя | Local-режим не стартует | Адрес хоста в `.env`, health-check провайдера, раздел в README |
| Низкое качество retrieval на русском | Средняя | Ответы не по теме | Гибридный поиск, инструкции Qwen3, чанки по заголовкам MD, тюнинг по golden set |
| Галлюцинации и ответы «из головы» | Высокая | Провал приёмки | Жёсткий промпт, порог релевантности, обязательные цитаты, проверка ключевых фактов |
| Расхождение контрактов между участниками | Средняя | Интеграция ломается | Контракт фиксируется в спеке до параллельной работы; CI на схему API |
| Корпус и вопросы к RAG готовят разные люди | Средняя | Вопросы не покрывают БЗ | Сверка тем golden set с манифестом корпуса до прогона |
| Remote-LLM видит текст вопросов, хотя логи обезличены | Средняя | Приватность | Предупреждение в UI; local-режим для чувствительных данных; не отправлять ПДн |
| Правовые ограничения на ГОСТы и книги | Средняя | Нельзя публиковать корпус | В git — только манифест; тексты на сервере; короткие цитаты |
| Не хватит времени на всё | Низкая | Недоделанный UI | Запас до 20.12; порядок работ: RAG и eval раньше UI |

## 7. Стратегия проверки

- **Юнит-тесты:** конвертация MD (эталонные файлы), чанкер (границы, overlap,
  `heading_path`), триггер переформулировки, маппинг цитат, Argon2id, права доступа.
- **Интеграционные:** `/api/...` с мок-LLM (`respx`), retrieval на тестовой коллекции
  Qdrant с 5–10 известными чанками, сброс пароля и отзыв сессий.
- **Провайдеры:** один набор тестов при `LLM_PROVIDER=openrouter` (мок) и `local`
  (LM Studio) — переключение режима не ломает пайплайн.
- **E2E-смоук:** регистрация → диалог → вопрос → ответ → источник → фидбек → выход;
  админ: загрузка → индексация → документ `ready` → поиск находит его фрагмент.
- **Оценка качества:** golden set 25+ вопросов, `Recall@5`, `MRR`, ragas
  (`faithfulness`, `answer_relevancy`, `context_precision`), покрытие ключевых фактов.
- **Ручные сценарии:** чек-лист из 10 пунктов (мобильный браузер, обрыв сети,
  длинный вопрос, вопрос вне домена, пустая БЗ, превышение лимита, скан-PDF).

Целевые пороги — в `constitution.md` §5.
