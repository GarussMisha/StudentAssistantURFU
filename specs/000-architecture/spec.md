# Спецификация: система «ИИ-ассистент по проектной деятельности»

> ID фичи: 000-architecture
> Статус: draft (решения команды от 2026-10-24)
> Дата: 2026-10-24

## 1. Проблема и цель

Студенты, работая над проектами, спотыкаются о методологию, а не о технологию: как
сформулировать ТЗ, какие артефакты нужны на каждом этапе, как распределить роли,
чем Scrum отличается от Kanban. Общие LLM отвечают правдоподобно, но не
проверяемо: сослаться на ГОСТ или Scrum Guide они не могут, а иногда выдумывают.

**Цель:** веб-сервис, который отвечает на методологические вопросы **только** по
заранее подготовленной базе знаний, показывает использованные фрагменты и честно
признаёт, когда ответа в базе нет.

**Что считается успехом:**
1. На этапе разработки сервис работает локально; к приёмке развёрнут и доступен
   тестировщикам по внешнему HTTPS-адресу.
2. Набор эталонных вопросов (25+) с ключевыми фактами и эталонными источниками;
   ответы проверены по формализованной методике, а не «на глаз».
3. Код и база знаний задокументированы; БЗ наполняется на сервере и не хранится в git.

## 2. Роли и пользователи

| Роль | Что делает | Как попадает в систему |
|------|------------|------------------------|
| **Студент** | Задаёт вопросы, читает ответы и источники, ведёт диалоги, ставит оценки | Регистрация по email и паролю |
| **Преподаватель / тестировщик** | Проходит сценарии, проверяет релевантность, смотрит отчёт оценки | Регистрация как студент + доступ к отчёту |
| **Администратор** | Управляет БЗ, документами, пользователями, сбросом паролей | Первый пользователь, создаётся при старте из переменных окружения |

Администратор работает через отдельную веб-страницу, а не через CLI. Ролей две:
`user` и `admin`; промежуточных ролей и granular-прав нет.

## 3. User stories

- **US-01** (must) Как студент, я хочу задать вопрос по методологии проекта и
  получить ответ с указанием источников, чтобы доверять ответу и проверять его.
  - **AC:** ответ приходит в чат; под ответом ≥ 1 источник; источник раскрывается
    до фрагмента текста; при отсутствии данных в БЗ ответ содержит явный отказ.

- **US-02** (must) Как студент, я хочу уточнять вопрос в том же диалоге, чтобы не
  переписывать контекст.
  - **AC:** вопрос-продолжение интерпретируется с учётом предыдущих сообщений;
    окно контекста ограничено бюджетом токенов модели, старые сообщения не ломают
    ответ; источники соответствуют уточнённому запросу.

- **US-03** (must) Как студент, я хочу возвращаться к прошлым диалогам, чтобы
  продолжать работу над проектом.
  - **AC:** список диалогов с датой и заголовком; открытие восстанавливает переписку
    с источниками; чужой диалог недоступен.

- **US-04** (should) Как студент, я хочу оценить ответ, чтобы отметить неудачные
  ответы.
  - **AC:** лайк/дизлайк сохраняется; для дизлайка можно выбрать причину; оценка
    привязана к сообщению.

- **US-05** (must) Как новый пользователь, я хочу зарегистрироваться без лишних
  шагов, чтобы начать работу сразу.
  - **AC:** форма просит email, пароль и повтор пароля; подтверждение по почте не
    требуется; после регистрации пользователь сразу авторизован.

- **US-06** (must) Как администратор, я хочу управлять базой знаний со страницы
  администратора, чтобы не зависеть от разработчика.
  - **AC:** вижу список документов и статусы; загружаю файл; запускаю индексацию;
    вижу причину ошибки; во время переиндексации сервис продолжает отвечать.

- **US-07** (must) Как преподаватель, я хочу видеть отчёт оценки качества, чтобы
  принять результат.
  - **AC:** есть набор ≥ 25 вопросов с ключевыми фактами и эталонными источниками;
    отчёт показывает retrieval-метрики, покрытие ключевых фактов и список провалов.

- **US-08** (should) Как студент, я хочу открыть источник ответа, чтобы прочитать
  первоисточник.
  - **AC:** карточка источника показывает документ, раздел/страницу и цитируемый
    фрагмент.

- **US-09** (must) Как администратор, я хочу сбросить пароль пользователя, чтобы
  он мог вернуться в систему без почтового сервиса.
  - **AC:** генерируется новый пароль, показывается один раз; старые сессии
    пользователя отзываются; сам пароль в логи не попадает.

## 4. Функциональные требования

| ID | Требование | Как проверить |
|----|------------|---------------|
| FR-001 | Регистрация: email + пароль + повтор пароля, проверка формата и совпадения, без подтверждения email | Тест API: успех; дубликат email → 409; несовпадение паролей → 422 |
| FR-002 | Вход, выход, серверная сессия в HttpOnly-cookie (SameSite=Lax, Secure в prod) | После logout защищённый маршрут → редирект/401 |
| FR-003 | При первом запуске создаётся администратор из `ADMIN_EMAIL` и `ADMIN_PASSWORD`; повторный запуск не создаёт дубликат | Чистая БД + старт → один admin; второй старт → всё ещё один |
| FR-004 | Страница администратора: документы, статусы, запуск индексации, список пользователей | Ручной сценарий под admin; для `user` → 403 |
| FR-005 | Сброс пароля администратором: генерация нового, показ один раз, отзыв сессий пользователя | Сброс → старый пароль не работает, новый работает |
| FR-006 | Создание, переименование и удаление диалога | Тест API + UI-сценарий |
| FR-007 | Отправка вопроса и потоковая выдача ответа (SSE) | Ответ появляется постепенно; событие `done` закрывает поток |
| FR-008 | Ответ формируется RAG-пайплайном: поиск по БЗ → контекст → генерация | В логах запроса есть чанки и их scores |
| FR-009 | Каждый содержательный ответ содержит ссылки на использованные фрагменты | ≥ 1 источник при содержательном ответе |
| FR-010 | При отсутствии релевантных фрагментов — отказ без домысливания | Вопрос вне БЗ → шаблонный отказ + список тем |
| FR-011 | Контекст диалога — скользящее окно по бюджету токенов модели; старые сообщения отбрасываются из промпта, но остаются в истории | Длинный диалог: ответ не превышает лимит контекста, история целиком видна в UI |
| FR-012 | История диалогов доступна только владельцу | Чужой `conversation_id` → 404 |
| FR-013 | Оценка ответа: лайк/дизлайк, причина для дизлайка, необязательный комментарий | Тест API + запись в БД |
| FR-014 | Загрузка документа администратором: PDF, DOCX, Markdown, HTML | По одному файлу каждого формата → документ создан |
| FR-015 | Перед чанкингом документ конвертируется в Markdown; исходный файл сохраняется | Для PDF/DOCX/HTML в БД есть `markdown_path`, текст совпадает с оригиналом по смыслу |
| FR-016 | Статусы обработки: `pending / processing / ready / failed` с причиной; неподдерживаемый формат и скан без текстового слоя → `failed` | Битая/скан-PDF → `failed` + понятная причина |
| FR-017 | Переиндексация без простоя: новая версия индекса подменяет старую атомарно | Во время индексации чат отвечает; после — новые чанки в выдаче |
| FR-018 | Метаданные документа и чанка: название, автор, год, раздел, страница, источник — для цитат, управления БЗ и контекста модели | Карточка источника и payload чанка содержат все поля |
| FR-019 | Просмотр фрагмента источника из ответа | Клик по источнику раскрывает текст и метаданные |
| FR-020 | Ограничение частоты запросов на пользователя | Превышение → 429 с понятным сообщением |
| FR-021 | Набор ≥ 25 эталонных вопросов: ключевые факты + эталонные источники; скрипт формирует отчёт | Прогон одной командой → `eval/report.md` |
| FR-022 | К приёмке сервис доступен по HTTPS на внешнем адресе | Проверка с телефона вне сети вуза |
| FR-023 | Структурированные обезличенные логи: `request_id`, длительность, модель, число чанков; без email, IP и `user_id` | По `request_id` восстанавливается путь запроса, но не личность |

## 5. Нефункциональные требования

- **Язык:** ответы и интерфейс на русском; английские термины (Scrum, backlog) — допустимы.
- **Скорость:** p90 первого токена ≤ 4 с, полный ответ ≤ 15 с при лимите 1200 токенов; retrieval ≤ 1.5 с.
- **Нагрузка:** 20–40 документов в БЗ; до 10 одновременных пользователей, до 100 запросов в сутки.
- **Доступность:** ≥ 95% в период приёмки; деградация без потери истории.
- **Сроки:** готовность к приёмке — до 20.12.2026.
- **Безопасность и приватность:** пароли хранятся только как необратимый хеш
  Argon2id; email — единственные персональные данные; HTTPS; HttpOnly-cookie;
  CSRF-токен на POST; проверка владельца ресурса; секреты вне git; логи обезличены;
  БД, файлы БЗ и резервные копии — на территории РФ.
- **Режимы работы:** разработка — localhost, LLM и эмбеддинги локально (LM Studio);
  продакшен — VPS, на нём только приложение и БД, LLM и эмбеддинги вынесены за API.
- **Переносимость LLM:** переключение local ↔ remote — переменными окружения
  (`LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`), без правки кода.
- **Бюджет:** хостинг ≤ 1000 ₽/мес; LLM в local-режиме — 0 ₽; в remote — по факту потребления.
- **Тесты:** критические модули (auth, retrieval, контракты API, конвертация и чанкинг) покрыты pytest.

## 6. Краевые случаи и ошибки

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| LLM вернул 429/5xx | 1 повтор, затем fallback-модель, затем сообщение об ошибке без потери вопроса |
| Локальный LLM-сервер не запущен | Сообщение «LLM недоступен» с подсказкой проверить LM Studio и `LLM_BASE_URL`; вопрос сохраняется |
| Сервис эмбеддингов недоступен | Индексация → `failed` с причиной; чат отвечает ошибкой деградации, история не теряется |
| Нет чанков выше порога релевантности | Отказ по шаблону + 3–5 тем, по которым БЗ отвечает |
| Вопрос вне домена | Вежливый отказ с указанием специализации ассистента |
| Очень длинный вопрос (> 2000 символов) | Обрезка до лимита + предупреждение в UI |
| База знаний пуста / не проиндексирована | Сервис работает, отвечает «база не загружена», health-check `degraded` |
| Загружен неподдерживаемый формат | `failed` + список поддерживаемых форматов |
| Скан PDF без текстового слоя | `failed` + причина «нет текстового слоя, требуется OCR» |
| Файл больше лимита (50 МБ) | Отказ до сохранения + сообщение о лимите |
| Повторная загрузка того же файла | Определяется по checksum: предупреждение и пропуск либо новая версия |
| Дубликат email при регистрации | 409 + понятное сообщение, форма сохраняет введённое |
| Истёкшая или отсутствующая сессия | Редирект на вход, после входа возврат на исходную страницу |
| Пользователь забыл пароль | Обращается к администратору; тот сбрасывает пароль на странице админа |
| Обрыв соединения во время стрима | Ответ досохраняется в истории; при повторном открытии виден целиком |
| Prompt injection в вопросе или документе | Инструкции не меняют роль и правила цитирования |
| Одновременная индексация и запросы | Поиск идёт по предыдущей версии коллекции |
| Контекст диалога превышает окно модели | Старые сообщения отбрасываются из промпта, история сохраняется |
| Admin-переменные не заданы при первом старте | Приложение падает на старте с явной ошибкой, а не создаёт админа с пустым паролем |

## 7. Что НЕ входит в объём

- Подтверждение email и восстановление пароля по ссылке (только сброс администратором).
- OCR сканированных PDF (в MVP такие файлы отклоняются с причиной).
- Telegram-бот, мобильное приложение, голосовой ввод.
- Загрузка файлов обычными пользователями (только администратор).
- Мультиязычность, кроме русского.
- Fine-tuning и обучение собственных моделей.
- Биллинг, подписки, тарифы.
- Расширенная админ-CMS, аналитические дашборды, granular-права и роли кроме `user`/`admin`.
- Интеграция с SSO УРФУ и учебными системами.
- Юридическая гарантия точности нормативных документов.
- Публикация полных текстов ГОСТов и книг.
