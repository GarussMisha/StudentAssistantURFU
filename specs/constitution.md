# Принципы проекта

> Проект: StudentAssistantURFU — ИИ-ассистент по проектной деятельности (RAG)
> Обновлено: 2026-10-24

## 1. Стек и язык

- Python 3.14, FastAPI + Jinja2 + HTMX (без SPA-фреймворка).
- PostgreSQL 16 — источник истины; Qdrant — векторный индекс.
- LangChain только для LLM-клиента, промптов и сплиттеров; retrieval — через `qdrant-client`.
- LLM — универсальный `LLMGateway` поверх OpenAI-совместимого протокола: remote API (OpenRouter) или локальный сервер LM Studio (`http://127.0.0.1:1234/v1`). Провайдер и модель задаются конфигом, код не меняется.
- Эмбеддинги — `text-embedding-qwen3-embedding-0.6b` через OpenAI-совместимый `/v1/embeddings`: LM Studio в разработке, внешний провайдер в проде. Приложение не держит модель в памяти.
- Документы БЗ конвертируются в Markdown один раз при загрузке; чанкинг, цитаты и просмотр работают с Markdown.
- Развёртывание — `docker compose` на одном VPS. Интерфейс, документация и ответы — на русском.

## 2. Стиль кода

- Структура: `app/{api,web,core,services,rag,db}`; бизнес-логика не живёт в роутерах.
- `ruff` (lint + format), длина строки 100, type hints в публичных функциях.
- Имена: `snake_case` — Python, `PascalCase` — классы, `kebab-case` — URL, `snake_case` — таблицы БД.
- Конфигурация только через `pydantic-settings` + `.env`; магических констант в коде нет.

## 3. Обязательные практики

- Каждая фича проходит: `spec.md` → `plan.md` → `tasks.md` → код → сверка.
- Контракты (схема БД, формат API, формат манифеста БЗ) фиксируются в спеке до начала параллельной работы.
- Тесты `pytest` на критичные модули: auth, retrieval, контракты API, конвертация и чанкинг документов.
- Любое изменение схемы БД — через миграцию Alembic.
- Секреты только в `.env`; в репозитории — `.env.example` без значений.
- Коммиты по Conventional Commits; ветка `main` всегда рабочая.
- Перед сдачей: отчёт оценки качества на 25+ вопросах + README с инструкцией запуска.

## 4. Запреты

- Отвечать на вопросы вне домена проектной деятельности «из общих знаний» модели.
- Хранить полные тексты документов БЗ в git (только манифест и ссылки).
- Коммитить `.env`, дампы БД, веса моделей, корпус БЗ и персональные данные.
- Логировать email, IP и `user_id`; писать пароли в логи и сообщения об ошибках.
- Добавлять зависимость без обоснования в `plan.md`.
- Подключать платные API без записи в бюджете проекта.

## 5. Критерии качества

- Каждый содержательный ответ содержит ссылку на источник либо явный отказ.
- p90 времени до первого токена ≤ 4 с; полный ответ ≤ 15 с.
- Recall@5 на golden set ≥ 0.8; faithfulness ≥ 0.85; покрытие ключевых фактов ≥ 80%.
- Сервис доступен по HTTPS; регистрация, вход, история диалогов и админ-страница работают.
- Готовность к приёмке — до 20.12.2026.
